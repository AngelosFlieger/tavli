## State and command flow

**Automatic opening:** `src/game/session/opening-authority.ts` samples one owned die per player in
paired attempts and applies the entire history through one deterministic transition. Local and
online authority advance immediately to the winner's normal `WAITING_FOR_ROLL` state. The online
wire projects the authoritative attempt history as one revision-bound `OPENING` presentation job;
its values must exactly match the resolved `GameState.opening.attempts`. The dice scene colors and throws both
dice together, while `PresentationCoordinator` makes interruption and missing-renderer completion
safe. This path has no opening clock or player command.
HUD and controller roll actions are disabled until `WAITING_FOR_ROLL`, and the online lobby rejects
an early roll intent at its trust boundary. Persisted matches from the former manual flow are
upgraded on reconnect by one authority transition and one monotonic `OPENING` revision.

**Local:** Board input in `src/scene/board-input.ts` sends intents through `checkers.ts` to `src/app/gameplay-actions.ts`. The action flow calls the `GameController` compatibility facade. `InteractionController` owns transient operation, ability-selection, legal-move cache, and held-checker state; the facade routes accepted intentions to `LocalAuthority`. That service owns the local `Session`, injected randomness, deterministic `transitionSession` calls, semantic-event message formatting, and undo history. A sampled roll is stored in the interaction controller's typed presentation operation, then `src/scene/dice.ts` presents those forced values before the action flow submits them to local authority. An accepted move updates authority immediately, then the action flow asks the scene to animate it and releases the matching move operation on completion. Resize can finish an interrupted local presentation once; a late animation callback is ignored and cannot release a newer operation. Undo restores one saved pre-action `GameState` from the local authority history.

**Online:** `src/app/match-session.ts` coordinates search, pairing, cancellation, rematch messaging, table exit, and disconnect through transport and UI ports. Its lifecycle is a discriminated `IDLE | SEARCHING | PLAYING` state, and the match cursor exists only while playing, preventing an unrelated failed start or search toggle from clearing live authority. `src/net/client.ts` opens `/ws`, sends `{type: 'hello', protocol}` first, and accepts gameplay traffic only after `ready`/`resume`; incompatible or unauthenticated clients receive a typed rejection. Protocol v3 requires a `{matchId, revision}` cursor on matched, resumed, and update messages. Every gameplay command is an envelope containing a command ID, match ID, expected revision, and typed intention. The server accepts only the current protocol version. It rejects a mismatched match/revision without mutation and returns a command-specific accepted/rejected result only to the sender. `OnlineAuthorityClient` owns the local online seat, monotonic command IDs, pending command identity, acknowledgement, and send port. The online flow rejects older revisions, foreign-match updates, duplicate results, and acknowledgements that do not belong to that pending operation. `gameplay-actions.ts` passes user intentions to `GameController`, which selects local behavior or routes `{type: 'roll' | 'move' | 'undo' | 'end' | 'restart' | 'forfeit' | 'pickAbility' | 'playAbility'}` through the online authority port; `end` may carry one validated `WITH_END_TURN` activation, while `playAbility` covers the post-roll window. `src/net/lobby.ts` owns the authoritative session, separates matchmaking queues by ruleset/config hash, checks the sender's seat and turn, samples draft, Recast, and passive dice randomness, and applies pure transitions. `server/index.ts` broadcasts state plus a validated discriminated presentation job: `DICE`, `MOVE`, or `RESET_DICE`. At most one job is currently accepted per revision; the outer cursor is its identity. Stored legacy hints migrate into jobs; older sockets are rejected during the handshake. Draft order attempts already live in authoritative state and are not duplicated in the update envelope. `src/app/online-game-flow.ts` adopts each accepted authoritative state before starting dice or move presentation. `src/app/presentation-coordinator.ts` supplies an independent presentation-only blocker and completion ticket, so resize, a newer update, or a late callback cannot delay or mutate authority. The flow calls scene and dice presentation through a small interface without importing Three.js. Malformed packet shapes return `INVALID_COMMAND`; valid-shaped but illegal, out-of-turn, or stale commands return an unchanged authoritative update with a typed command result. Resigning ends the session with the opponent as winner, and the server keeps a finished match in place until both players accept a rematch.

`GameState` is the shared contract. It contains the board and off trays, phase, active player, physical roll, roll source, unused movement tokens, public dice modifiers, a discriminated pending-or-resolved opening, outcome, ruleset, variant-config hash, and nullable powerup state. A resolved opening owns its complete paired-attempt history and winner, so those facts cannot disagree. Classic state uses `CLASSIC`, a null hash/source, no modifiers, and null powerup state. A powerup session tracks completed rounds, public loadouts, effects, passive counters, config-resolved passive policy snapshots, turn usage, and a discriminated draft state. `src/game/session/invariants.ts` defines semantic state invariants independently of transport and persistence; transition traces exercise it and the store applies it after structural decoding so contradictory persisted sessions cannot resume. `Update` adds `canUndo`, semantic events, and discriminated presentation jobs because online clients do not own the server's history or authority. Wire messages are JSON. MongoDB stores accounts, login sessions, profile-separated queue entries, and each match as the two seat account ids, complete session document, immutable resolved variant-configuration snapshot, connection flags, and the latest accepted revision's event/presentation envelope. The envelope omits state and undo history; the server combines it with the stored session to reproduce dice, reroll, and move presentation. Stored sessions are structurally and semantically validated before resume: phase, 24-point board, two off trays, exactly 30 unique checker ids, dice ranges, opening attempt history, outcome shape, phase relationships, checker ownership, ruleset, and configuration hash must all agree. The persistence decoder upgrades legacy `OPENING_ROLL` snapshots and their parallel opening fields before validation. One game server owns live authority for a database. Per-match mutation queues serialize commands, reconnect/disconnect, cancellation, timeout, and stale-match claims; guarded claims re-read persistence while holding that queue. On startup it clears volatile queue rows, persists each live match’s paused clock and away state, then restores matches as players reconnect. A paired seat that has connected before gets a 45-second reconnect grace; a seat that never connected gets 20 seconds. Forfeit, disconnect, no-show, cancellation, and normal completion persist a typed `Outcome.kind`, final position, and winner. A finished game remains the active match until both players accept a rematch, which starts a new document with the same rules context. Online state also carries a `GameClock` with a running deadline or paused remaining time. `src/game/clock.ts` owns start, pause, resume, expiry, environment parsing, and formatting. Opening, drafts, and disconnects do not consume player time; the server checks expiry during its sync loop and claims the timeout with the same revision-guarded end path used by forfeits. There is no currency ledger.

The pure board rules live in `src/game/rules/`. `src/game/session/transition.ts` accepts one typed command and an immutable session input (`GameState` plus undo history), then returns a new session and semantic events or a rejection. It validates the phase, dice, legal move sequence, and intermediate landings. Events identify moves, fresh pins, bear-offs, roll outcomes, turn changes, and game results. `session/messages.ts` formats the existing status text from those events; `LocalAuthority` and the server apply the transition directly. `session/game.ts` remains as a compatibility facade for regression tests. `session/phase.ts` contains only authoritative turn phases. The controller is an interaction compatibility facade and uses one discriminated operation state for local rolls and moves while keeping ability targeting separate. Its online helper records pending command identity before sending; authoritative adoption clears only that command operation. Presentation lifetime and stale callback protection are owned by `PresentationCoordinator`, not the controller. `src/game/engine.ts` remains a compatibility entry point for older rule and test imports. The target Functional Core, Imperative Shell structure and its migration stages are in [the refactor plan](refactor-plan.md).

### Multiplayer connection feedback

Starting public matchmaking enters a visible `CONNECTING` presentation state immediately, before
the WebSocket handshake is ready. Once the server confirms the queue entry, the same waiting screen
changes to `SEARCHING`. Temporary connection failures retain unsent matchmaking packets across the
bounded reconnect attempts; a reconnect while queued returns to `CONNECTING`, and only final retry
exhaustion clears the request and returns to the title screen. This UI status is a projection of the
connection lifecycle and does not advance or duplicate match authority.

### Deployment constraint

Exactly one active game-server process may own live matches in a database. The per-match mutation
queue is process-local: it prevents concurrent mutations inside that server, but it is not a
distributed lock. Running multiple active game servers against the same database could let two
processes handle the same match concurrently. Active-active scaling therefore requires an explicit
cross-process ownership mechanism, such as database-backed match leases, distributed locks, or
transactional command processing, before additional game-server instances are enabled.

## Rendering and assets

`createStage` loads `Board.glb`, configures cameras, lights, postprocessing, and the render loop. `createGameplay` loads two checker models and creates 30 visual checker instances. `board-presentation.ts` maps logical positions to checker transforms, including pinned stacks, trays, and the opening deal. `board-input.ts` raycasts against 24 point targets and emits pickup, release, clear, and placement intents; the controller applies selection changes and `checkers.ts` emits accepted placement intents to `gameplay-actions.ts`. `src/ui/gameplay-hud.ts` renders the turn buttons, status, player panels, and held-checker choices, and emits control actions through `checkers.ts` to the action flow. It composes the thin `src/ui/draft-panel.ts` boundary over `src/ui/abilities`: `draft-dialog.ts` owns modal draft and order reveal, `card-content.ts` supplies reusable configured card content, `loadout-stack.ts` owns overlapping inventories, `focused-ability-card.ts` owns details and Use interaction, and `active-effect-list.ts` formats public effects. `presenters.ts` is the complete ability-ID UI registry for counter copy, roll prompts, option labels, and direct-die hints; it formats controller-provided legal choices without deciding legality. `src/app/pickup-selection.ts` owns the held-checker queue, filters legal choices, and revalidates remaining selections after each accepted move. `src/game/pickup.ts` checks queue feasibility against the dice; each resulting move still passes through normal engine and online validation. `move-preview.ts` makes temporary visual copies for held checkers and the next hovered landing; these copies do not change game state. `move-animation.ts` owns checker interpolation and the pin impact. Intermediate combined-move landings remain visible and rules-validating, but only a pin on the final landing receives the slow-motion impact. After a local animation completes, `gameplay-actions.ts` releases the controller input lock and revalidates held checkers. For an online move, the flow snapshots the prior visual position, adopts the authoritative result, and animates from that snapshot; completion only releases the presentation blocker and resynchronizes the board. The landing ghost and halo render above destination highlights. A final fresh pin moves slowly at first, accelerates into contact, zooms toward the landing point, then shakes and briefly brightens the canvas. This effect respects reduced-motion and motion preferences. `createDice` loads `Die.glb`, animates results, positions accessible HTML hit targets over Recast-eligible dice, and can throw a single authority-identified die while leaving its partner still. `src/scene/layout.ts` changes presentation for portrait view without changing logical movement. Home, title, and waiting decorations are separate scene helpers. Runtime models live under `public/models`; `assets/source/build_assets.py` generates files under `assets/source/generated/` and does not overwrite runtime models.

The ability draft UI presents the final decisive authoritative order attempt once, with one player-colored animated CSS die per avatar; these dice never feed movement or choose an outcome. Authority still records and resolves ties, but the dialog does not replay those internal attempts. Once the reveal finishes, the current picker's avatar remains next to the dialog. The shared bottom inventory slot shows only the active player's overlapping, focusable card stack; it sits immediately right of the Roll control on landscape screens and above the controls when portrait width is constrained. A turn change slides the outgoing tray toward its player side and the incoming tray in from the other side. It remains separate from the player avatar panels and retains a distinct explicit Use action. `src/scene/ability-effects.ts` derives temporary Frost Seal and Bastion board aids from public effect state; the translucent ice, ghost checker, and icons are non-interactive presentation and do not participate in rule evaluation or picking.

## Development commands

Node.js 24.11+ is required. Node 26 LTS is the recommended development runtime and the primary CI baseline; verification also runs on the minimum supported release.
Run `npm ci` once, then:

| Command                     | Effect                                                                                                                                   |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run dev`               | Bundles the server, runs it on port 3001, and starts Vite on port 3000 with `/ws` proxied to 3001.                                       |
| `npm test`                  | Discovers and runs all `tests/*.test.ts` files directly through the TypeScript loader.                                                   |
| `npm run test:coverage`     | Runs the unit suite with enforced line, branch, and function coverage floors.                                                            |
| `npm run test:property`     | Runs generated reachable Classic and Powerups sessions through deterministic transitions and invariant contracts.                        |
| `npm run test:mutation`     | Mutation-tests pure movement, position, outcome, and opening authority with a fresh focused test run.                                    |
| `npm run test:mutation:dry` | Validates mutation instrumentation and its focused test command without executing mutants.                                               |
| `npm run lint`              | Runs type-aware Oxlint checks through `tsrs`, including unsafe floating-promise and async-handler detection.                             |
| `npm run test:browser`      | Starts isolated web/game servers and checks local interaction plus authoritative two-seat drafts, activation, and replacement in Chrome. |
| `npm run build`             | Type-checks, builds the browser into `dist/`, and bundles the server into `dist-server/`.                                                |
| `npm start`                 | Serves `dist/` and `/ws` from one process on port 3000 or `PORT`.                                                                        |
| `npm run format:check`      | Checks Prettier output and semantic spacing between logic phases.                                                                         |

The pure rules and session are the natural places to introduce a ruleset or mechanic state. Any online mechanic also needs a protocol representation, server validation, and client presentation. Keep random decisions and effect resolution explicit in shared state so the UI can display them and both clients stay synchronized. Add tests at the rules, session, and lobby boundaries before visual polish. The browser smoke runner uses the system Chrome/Chromium through `playwright-core`; `PLAKOTO_CHROME_PATH` overrides executable discovery. Its injected client selects the registered one-round `fast-balance` profile so two real drafts, activation, and replacement are covered without changing the public `powerups-v1` selection. The runner also supplies the environment-only `PLAKOTO_TEST_RANDOM_SEED` to the server authority so Recast is offered deterministically; that seed also feeds a separate seeded dice stream, so a smoke match replays the same rolls while draft and passive draws keep their own sequence. Normal servers do not set it, clients cannot provide it, and production randomness remains backed by `node:crypto`. Smoke pages render at a quarter of the device resolution with reduced motion, and the smoke server runs with `PLAKOTO_CLOCK=off`: software WebGL would otherwise drop to three frames per second, and every Playwright action waits on frames, so a single click would cost seconds and the authoritative opening clock would expire before the scripted rolls finish. Device scaling changes only raster resolution, not CSS layout or pointer coordinates. The runner picks a free adjacent port pair and tears down Chrome, Vite, the bundled server, and the in-memory MongoDB on exit or interrupt, so interrupted runs cannot block the next one. Clock expiry behavior stays covered by unit tests rather than the browser path.

`src/ui/shell.ts` composes the browser chrome and forwards navigation calls. `title-screen.ts` owns the start menu, the Classic/Powerups choice, the private-room panel, and the matchmaking state, then sends one typed `MatchSelection` to local setup or matchmaking. `overlay.ts` owns the shared dialog mechanics; `settings-dialog.ts` covers preferences, language, saved matches, restart, table exit, and the development playtest sections; `help-dialog.ts` derives rules copy from the resolved ability definitions; `history-list.ts`, `playtest-tools.ts`, and `playtest-analysis-panel.ts` own their panels, and the shared `download.ts` saves development reports. The waiting screen and gameplay HUD show the selected profile. `rules-context.ts` is the shared selection, queue-key, snapshot, and state-validation boundary used by local setup, matchmaking, legacy restore, and online join; unknown profiles and mismatched snapshots are rejected. `src/game/variant/config` validates and deeply freezes complete profiles and assigns deterministic hashes. `abilities/catalog.ts` is the only ability registry: it derives `AbilityId`, the config map, metadata, and the capability maps from the definition modules, so adding an ability means one definition module plus a catalog line, a balance-profile entry, and catalog copy. `abilities/` owns shared definition and capability infrastructure; concrete definitions remain separated into `powerups/definitions` and `passives/definitions`. Each definition owns its config type, validation, copy references, and the behavior its kind/timing requires (enforced by `defineAbility` overloads). Frost Seal, Bastion, and Jinx colocate their pure end-turn targeting, effect construction, and effect-validity capabilities; Clear Skies colocates its before-roll targeting and effect-removal capability; Recast, Nudge, and Opportunist colocate their after-roll options, authority-randomness requirements, application, and resource hooks. `abilities/behavior-registry.ts` aggregates those timing capabilities and preserves ID/config type correlation. `passives/capabilities.ts` defines passive roll, movement, inventory, powerup-use, counter, and lifecycle hooks; `passives/behavior-registry.ts` composes the hooks exported beside Loaded Knuckles, Quartermaster, Home Guard, and Opportunist. `passives/policy.ts` is a compatibility facade over that registry rather than an ability-specific switchboard. `abilities/roll-adjustment.ts` shares bounded numeric-die option and application logic between Nudge and Opportunist. `transitionSession` receives an explicit immutable rules context, counts configured rounds, owns draft phase transitions, and applies powers through timing-specific pure commands. `activation.ts`, `powerups/before-roll.ts`, and `roll-activation.ts` coordinate timing, inventory/resource consumption, and public state without owning concrete ability rules. `powerups/roll-effects.ts` interprets public `DICE_PENALTY` constraints against effective movement tokens while preserving physical dice and recording public dice modifiers. `move-policy.ts` interprets `BLOCK_LEAVING` and `BLOCK_LANDING` constraints from active effects after baseline Plakoto generates candidate landings; definitions publish serializable constraints and keep their targeting/validity behavior, so consumers do not switch on ability IDs. Local play and the online authority use the same boundaries; the server supplies draft, Recast, and passive-roll randomness and rejects stale instances, unearned Focus, or illegal targets.

The staged follow-up work for persistence, typed ability behavior capabilities, controller workflow state, and reusable ability UI is tracked in [the variant implementation improvement plan](variant-implementation-improvements.md).

In development, `src/game/random.ts` supplies a stable seeded `RandomInt` for explicit local playtest seeds. The seed field in Settings is blank by default, so ordinary development games retain the cryptographic source just like production local games; online games always retain server-owned randomness. `src/app/playtest-report.ts` subscribes to accepted controller events and stores only an in-memory, schema-versioned report. Each entry pairs semantic events with a compact public state snapshot so effect duration, offers, inventory, rolls, stalls, and outcomes can be analyzed without scraping UI copy. `src/app/playtest-analysis.ts` validates imported schema-one reports, groups them by ruleset/profile/configuration hash, and derives offer/pick/replacement/use, hold-duration, stall, game-length, and winner correlations. Unfinished observations remain explicitly censored. The shell can download both raw and aggregate JSON in development; neither path has a network sink. The development profile selector resolves only IDs in the normal closed registry and never changes online authority.

## Water art preview

`src/scene/water-sweep.ts` owns four pooled instanced meshes: a full-width flood volume, surface whitewash, breaking lip parcels, and spray. Three following crests travel at different speeds, catch one another, and leave a shallow, churning wash behind. Compact lip clusters and droplets use ballistic downward acceleration, so the effect collapses forward onto the following swells rather than translating one rigid sculpture. The water then recedes over a 7.3-second cycle, with a continuous irregular shoreline retreat after the crests pass. Standing water is clipped to the felt playing fields. Passing crests, foam, and spray may cross above the center bar only when their lower bounds clear its top; the receding film never occupies the center. Side trays and outer rails stay dry. The effect follows the board's visual depth but receives no checker objects, session state, physics world or network transport. `src/ui/water-preview.ts` wires the temporary **Test Water** button and lifecycle from `main.ts`. Reduced motion or disabled ambient motion shows a stationary 1.2-second shallow wash. Leaving the table cancels the preview. This is not a registered ability and does not affect gameplay.
